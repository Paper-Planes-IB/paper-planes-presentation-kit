# PP Interview Slides

Суб-скилл pp-slidument. Создаёт слайды на основе данных глубинных интервью (БПМ3).

> **Визуальный стиль, палитра, типографика, паттерны раскладки** — наследуются из `pp-slidument`.
> Этот скилл НЕ дублирует визуальные правила — он определяет только контентную структуру трёх типов слайдов.

---

## 0. КРИТИЧЕСКИЕ ПРАВИЛА

1. **Это БЛОК, не полная презентация.** Результат = 1–5 контентных слайдов. БЕЗ титульного, БЕЗ содержания, БЕЗ разделителей.
2. **Входные данные = БПМ3** (результаты глубинных интервью). Иногда дополнительно нужен БПМ2.
3. **Все правила pp-slidument действуют**: action titles, SCQA, плотность 1000+ символов, визуализация на каждом слайде, слева направо, минимум 10pt.
4. **Прямые цитаты обязательны.** Каждый тезис подкрепляется 1–3 цитатами респондентов в кавычках.
5. **Квантификация обязательна.** «12 из 15 респондентов», «78% опрошенных», не «многие отметили».

### Вариации нарезки данных

Каждый из трёх типов слайдов может иметь вариации — одни и те же данные нарезаются по разным осям:

| Вариация | Пример | Когда |
|----------|--------|-------|
| По компании в целом | Один слайд с общей картиной | По умолчанию |
| По продуктам | Отдельный слайд на каждый продукт/услугу | Если продуктов > 1 и различия существенны |
| По типам покупателей | Экономический, технический, эксплуатант (Авантпак) | B2B с разными ЛПР |
| По типам должностей | CISO, CTO, CIO, PM (Bizone) | B2B с разными ролями |
| По отраслям клиентов | Финсектор, госсектор, ритейл | Если клиенты из разных отраслей |
| По регионам | Москва, регионы, СНГ | Если география влияет на ответы |

**Правило:** если данные позволяют нарезку и различия между группами существенны — делай отдельные слайды по вариациям. Если различия минимальны — один общий слайд.

## 1. SI4a — ДРАЙВЕРЫ И БАРЬЕРЫ (хвалят / ругают)

### Суть
За что клиенты хвалят компанию, за что ругают, что побудило бы сменить поставщика.

### Входные данные
- Результаты БПМ3 (глубинные интервью)
- Количество и роли респондентов
- Прямые цитаты по каждой теме
- Желательно: квантификация (сколько из N отметили каждую тему)

### Паттерн верстки: Вариант А — две колонки (Bizone)

Когда: фокус на чёткое разделение «плюсы vs минусы».

```
┌──────────────────────────────────────────────────────┐
│ Action title: «Основные преимущества связаны с       │
│ работой команды, барьеры — с процессами и ценой»     │
├──────────────────────────┬───────────────────────────┤
│ ✅ ПРЕИМУЩЕСТВА           │ ❌ НЕДОСТАТКИ              │
│                          │                           │
│ ▪ Гибкость и адаптивность│ ▪ Недостаточность         │
│   «Продукт под нас       │   сквозных процессов      │
│   настроили, проблем нет»│   «Работаем с 4–5         │
│   «Встроились в нашу     │   менеджерами, кто что    │
│   кастомную шину»        │   меняет — не поймёшь»    │
│                          │                           │
│ ▪ Кастомизация           │ ▪ Слабая ориентация       │
│   «Глубоко разбираются   │   на бизнес               │
│   в архитектуре»         │   «Хочется отчёты,        │
│                          │   которые покажу           │
│ ▪ Быстрая поддержка      │   директору»              │
│   «Через чат пишем —     │                           │
│   вопрос решается        │ ▪ Сложности с ценой       │
│   в тот же день»         │   «Очень тяжело пробить   │
│                          │   такую цену без ROI»     │
├──────────────────────────┴───────────────────────────┤
│ Источник: глубинные интервью, N=XX, [период]         │
└──────────────────────────────────────────────────────┘
```

**Структура контента:**
- Левая колонка: 3–6 тем-преимуществ, каждая = название (bold) + 1–3 цитаты курсивом
- Правая колонка: 3–6 тем-недостатков, аналогично
- Action title = главный вывод: «Преимущества связаны с X, барьеры — с Y»

### Паттерн верстки: Вариант Б — матрица «Важность × Проявленность» (Авантпак)

Когда: нужно показать не только плюсы/минусы, но и приоритеты.

```
┌──────────────────────────────────────────────────────┐
│ Action title: «7 ключевых болей: стратегические      │
│ преимущества — менеджеры и надёжность,               │
│ критически исправить — качество и сроки»             │
├──────────────────────────────────────────────────────┤
│                                                      │
│   Важность →                                         │
│   ┌─────────────────────────────────────────┐        │
│   │  ○ Работа менеджеров  ○ Надёжность     │ Сильно │
│   │        (стратег. преимущества)          │ прояв- │
│   ├─────────────────────────────────────────┤ лено   │
│   │  ○ Качество    ○ Сроки     ○ Цена      │ Слабо  │
│   │        (критически исправлять)          │ прояв- │
│   └─────────────────────────────────────────┘ лено   │
│                                                      │
│ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐    │
│ │ Тема 1  │ │ Тема 2  │ │ Тема 3  │ │ Тема N  │    │
│ │ «цита-  │ │ «цита-  │ │ «цита-  │ │ «цита-  │    │
│ │  та»    │ │  та»    │ │  та»    │ │  та»    │    │
│ └─────────┘ └─────────┘ └─────────┘ └─────────┘    │
│                                                      │
│ Источник: глубинные интервью, N=XX, [период]         │
└──────────────────────────────────────────────────────┘
```

**Структура контента:**
- Верхняя часть: матрица 2×2 или scatter «Важность × Проявленность»
- Нижняя часть: карточки по каждой теме с цитатами
- Цветовое кодирование: зелёный = стратегическое преимущество, коралловый = критически исправить

### Вариации SI4a

При нарезке по типам покупателей/должностей — **отдельный слайд на каждый тип** с одинаковой структурой, но разным контентом. Action title каждого слайда отражает специфику группы:
- «CISO оценивают функционал и экспертизу, соответствие требованиям критично для фин/госсектора»
- «Для технического покупателя плёнка — это прежде всего операционная стабильность»

## 2. SI4b — МАТРИЦА NEED-HAVE

### Суть
Что нужно клиентам (need) и что есть у нас (have). Показывает совпадения и разрывы.

### Входные данные
- Результаты БПМ3 (глубинные интервью)
- Список факторов выбора / критериев принятия решения
- Оценка каждого фактора по группам (если есть вариации)
- Иногда нужен БПМ2 (анализ текущих возможностей компании)

### Паттерн верстки: Матрица факторов × ЛПР (Bizone)

```
┌──────────────────────────────────────────────────────┐
│ Action title: «Функциональность и экспертиза         │
│ важны для всех ЛПР, PM уникально ценят              │
│ минимизацию влияния на UX»                           │
├──────────────────────────────────────────────────────┤
│                                                      │
│ Фактор выбора          │ CISO │ CTO │ CIO │ PM     │
│ ────────────────────────┼──────┼─────┼─────┼────── │
│ Функциональность       │  ●   │  ●  │  ◕  │  ●    │
│ Интеграция в архит.    │  ◑   │  ●  │  ◕  │  ●    │
│ Технолог. стабильность │  ◕   │  ●  │  ●  │  ◕    │
│ Экспертиза команды     │  ●   │  ●  │  ◕  │  ◑    │
│ Поддержка              │  ◕   │  ◕  │  ◑  │  ◕    │
│ Миним. доп. затрат     │  ◑   │  ◑  │  ●  │  ○    │
│ Простота отчётности    │  ●   │  ○  │  ●  │  ○    │
│ Регуляторные требов.   │  ●   │  ◑  │  ●  │  ○    │
```

**Структура контента:**
- Таблица: строки = факторы выбора (10–20), столбцы = типы ЛПР или сегменты
- Значения: Harvey Balls (● ◕ ◑ ○) или цветовое кодирование (красный/жёлтый/зелёный)
- Группировка строк по категориям (если факторов > 12)
- Action title = главный паттерн из матрицы

SI4b часто имеет ghost slides — детализация каждого столбца (каждого типа ЛПР) на отдельном слайде с цитатами и пояснениями. Ghost slide использует Паттерн «Карточки» из pp-slidument:

## 3. SI5 — РАЗЛИЧИЯ КЛИЕНТОВ И НЕКЛИЕНТОВ

### Суть
Существуют ли устойчивые паттерны отличий между теми, кто уже работает с компанией, и теми, кто потенциально мог бы.

### Входные данные
- Результаты БПМ3 (интервью и с клиентами, и с неклиентами)
- По каждой теме: позиция клиентов vs позиция неклиентов
- Прямые цитаты обеих групп

### Паттерн верстки: Сравнительная таблица (Bizone)

Формат похож на SI4a (две колонки) и SI4b (матрица), но ось сравнения — «клиенты vs неклиенты».

```
┌──────────────────────────────────────────────────────┐
│ Action title: «Основные различия — в специфике       │
│ бизнеса и отрасли: на этом завязаны различия         │
│ во взглядах на поставщиков»                          │
├──────────────────────────────────────────────────────┤
│                                                      │
│ Тема / Фактор       │ Клиенты        │ Неклиенты    │
│ ─────────────────────┼────────────────┼────────────  │
│ Главный приоритет    │ Экспертиза     │ Цена         │
│                      │ «Глубоко раз-  │ «Нам нужен   │
│                      │ бираются»      │ просто        │
│                      │                │ функционал»   │
│ ─────────────────────┼────────────────┼────────────  │
│ Отношение к цене     │ Готовы платить │ Цена —        │
│                      │ за кастом      │ решающий      │
│                      │ «Цена ок, если │ фактор        │
│                      │ качество»      │ «Дорого без   │
│                      │                │ ROI»          │
│ ─────────────────────┼────────────────┼────────────  │
│ Процесс выбора       │ Длинный,       │ Тендерный,    │
│                      │ экспертный     │ формальный    │
│ ─────────────────────┼────────────────┼────────────  │
│ Ожидания от          │ Партнёр,       │ Поставщик,    │
│ поставщика           │ экспертиза     │ продукт       │
│                                                      │
│ ● совпадение  ▲ клиенты выше  ▼ неклиенты выше     │
├──────────────────────────────────────────────────────┤
│ Источник: глуб. интервью, клиенты N=X,              │
│ неклиенты N=Y, [период]                              │
└──────────────────────────────────────────────────────┘
```

**Структура контента:**
- Таблица: строки = темы/факторы (5–10), два столбца = Клиенты | Неклиенты
- Каждая ячейка: краткий тезис + цитата
- Цветовое кодирование: синий = совпадение, зелёный = клиенты сильнее, коралловый = неклиенты сильнее
- Action title = ключевой паттерн различий

### Альтернативный паттерн: карточки (при малом числе тем)

Если тем 3–4 — вместо таблицы использовать карточки в ряд, каждая карточка = одна тема с двумя секциями (клиенты / неклиенты).

### Вариации SI5

Те же что у SI4a/SI4b. Наиболее частая: по отраслям клиентов (клиенты из финсектора vs неклиенты из финсектора).

## 4. АЛГОРИТМ РАБОТЫ

```
1. Получи данные БПМ3 (интервью)
2. Определи, какие типы слайдов запрошены (SI4a, SI4b, SI5 — один или несколько)
3. Определи вариации нарезки (по компании, по продуктам, по типам ЛПР, по отраслям, по регионам)
4. Посчитай количество слайдов:
   - Один тип × одна вариация = 1 слайд
   - Один тип × N вариаций = N слайдов
   - SI4b с ghost slides = 1 матрица + N детализаций
   - МАКСИМУМ: 5 слайдов на тип. Если вариаций больше — группируй
5. Для каждого слайда:
   a. Сформулируй action title (вывод с данными, не тему)
   b. Выбери паттерн верстки из этого скилла
   c. Заполни контент: тезисы + цитаты + квантификация
   d. Добавь источник: «Глубинные интервью, N=XX, [период]»
6. Проверь по чек-листу pp-slidument
```
