## ИЗВЛЕЧЕНИЕ ДАННЫХ ДЛЯ ГРАФИКОВ

**ПРАВИЛО: Если в тексте есть числа → ВСЕГДА рассмотри график, прежде чем делать таблицу.**

### Паттерны текст → тип графика

| Паттерн в тексте | Тип графика | Пример |
|-----------------|-------------|--------|
| "X составляет Y%" (доли) | `pie` или `donut` | "IT составляет 35% бюджета" |
| "рост с X до Y за период" | `line` | "рост с 10M до 25M за 3 года" |
| "Q1, Q2, Q3, Q4" (периоды) | `column` или `line` | "выручка: Q1=42M, Q2=48M" |
| "категория A — X, B — Y, C — Z" | `column` или `bar` | "Россия — 45M, Казахстан — 12M" |
| "было X, стало Y, дельта Z" | `waterfall` | "было 100, +20 новые, −13 отток, стало 107" |
| "вклад X + Y + Z = Total" | `stacked_column` | "маркетинг + продажи + сервис = 100M" |
| "тренд за 5+ периодов" | `line` или `area` | "2020: 10M, 2021: 15M, ..., 2025: 42M" |
| "доли, сумма = 100%" | `donut` | "Digital 40%, Retail 35%, B2B 25%" |

### Алгоритм из 3 шагов

**Шаг 1: Сканируй числа**
Найди в исходном тексте все числовые значения: проценты, суммы, штуки, периоды.

**Шаг 2: Структурируй**
Определи:
- Есть ли ось времени? (Q1-Q4, 2020-2025, Jan-Dec)
- Есть ли категории? (продукты, регионы, отделы)
- Есть ли доли от целого? (проценты, сумма ≈ 100%)
- Есть ли декомпозиция? (факторы изменения, bridge)

**Шаг 3: Выбери подтип**

| Подтип | Когда использовать | Пример данных |
|--------|-------------------|---------------|
| `column` | Сравнение по категориям | Выручка по регионам |
| `bar` | Сравнение по категориям (длинные названия) | Выручка по 10 продуктам |
| `line` | Тренд во времени | Выручка Q1-Q4 |
| `stacked_column` | Состав по категориям во времени | Выручка по продуктам × кварталы |
| `pie` | Доли от целого (≤ 6 сегментов) | Структура затрат |
| `donut` | Доли от целого + число в центре | Доля рынка |
| `area` | Тренд с акцентом на объём | Рост базы пользователей |
| `stacked_area` | Тренд состава | Выручка по каналам за 5 лет |

### Примеры "Текст → JSON"

**Пример 1**: "Выручка компании выросла с 42M₽ в Q1 до 62M₽ в Q4 2025"

→ Тренд во времени → `line` или `column`:
```json
{
  "type": "chart",
  "title": "Выручка выросла на 48% за 4 квартала до 62M₽",
  "chart_type": "column",
  "categories": ["Q1", "Q2", "Q3", "Q4"],
  "series": [{"name": "Выручка, млн ₽", "values": [42, 48, 55, 62]}]
}
```

**Пример 2**: "Структура затрат: IT — 35%, маркетинг — 25%, логистика — 20%, HR — 12%, прочее — 8%"

→ Доли от целого → `pie` или `donut`:
```json
{
  "type": "chart",
  "title": "IT и маркетинг формируют 60% всех затрат компании",
  "chart_type": "donut",
  "categories": ["IT", "Маркетинг", "Логистика", "HR", "Прочее"],
  "series": [{"name": "Доля затрат", "values": [35, 25, 20, 12, 8]}]
}
```

**Пример 3**: "Выручка выросла на 15M₽: +20M новые клиенты, +8M рост чека, −13M отток"

→ Декомпозиция → `waterfall` (НЕ таблица!):
```json
{
  "type": "waterfall",
  "title": "Рост выручки на 15M₽ обеспечен привлечением новых клиентов",
  "items": [
    {"label": "Выручка Q1", "value": 100, "type": "total"},
    {"label": "Новые клиенты", "value": 20, "type": "relative"},
    {"label": "Рост чека", "value": 8, "type": "relative"},
    {"label": "Отток", "value": -13, "type": "relative"},
    {"label": "Выручка Q2", "value": 115, "type": "total"}
  ]
}
```

### Правило: ГРАФИК > ТАБЛИЦА

Если данные можно представить и графиком, и таблицей — **ВСЕГДА выбирай график**.

| Данные | ❌ Таблица | ✅ График |
|--------|----------|---------|
| Выручка Q1-Q4 | 4 числа в строке | `column` chart — видна динамика |
| Доли рынка 5 игроков | 5 строк × 2 столбца | `donut` — видно соотношение |
| Рост 2020→2025 | 6 строк | `line` chart — виден тренд |
| Бюджет по отделам | Список из 6 строк | `bar` chart — видно сравнение |

**Исключение:** таблица лучше графика когда:
- Нужны Harvey Balls / RAG-статусы
- Данные разнородные (текст + числа + статусы)
- Сравниваются 5+ объектов по 5+ разнородным параметрам
