## ПРАВИЛА ЦЕЛОСТНОСТИ ТЕКСТА

### Языковой стандарт

**ВСЕ слайды должны быть на русском языке**, если источник не на английском.

❌ **ЗАПРЕЩЕНО**:
- Частичный английский: "Результат performance review показал..."
- Смешивание языков: "Снижение engagement на 15%"
- Английские термины без перевода (кроме устоявшихся)

✅ **ПРАВИЛЬНО**:
- Полностью на русском: "Результат оценки эффективности показал..."
- Устоявшийся термин — оставляем: "Снижение NPS на 15%"
- Нужный термин — с переводом: "Time to Market (TTM, срок вывода на рынок)"

**Исключения (можно на английском):**
- Финансовые метрики: ROI, EBITDA, P&L, CAPEX, OPEX, IRR, NPV
- Устоявшиеся аббревиатуры: B2B, SaaS, API, CRM, ERP, NPS, CSAT
- Названия фреймворков: SCQA, MECE, RASCI, SWOT, PESTLE
- Названия компаний/продуктов: Google Analytics, Salesforce

**Англицизмы и кальки — расширенные правила:**

По умолчанию переводить на русский. Английский оставлять только если это общепринятый отраслевой термин. При первом упоминании давать русскую расшифровку.

| ❌ Англицизм | ✅ Русский эквивалент |
|-------------|---------------------|
| SKU | "Товарная позиция" (при первом упоминании: "SKU (товарная позиция)") |
| MVP | "Пилот" или "минимально жизнеспособная версия" |
| BCG (как название матрицы) | "Матрица роста и доли" (не использовать аббревиатуру) |
| A/B-тест | "Сравнительный тест" или "сравнение вариантов" |
| no-show | "Неявка" |
| M&A | "Слияния и поглощения" |
| TCO | "Совокупная стоимость владения" |
| must-have / nice to have | "Обязательное / желательное" |
| roadmap | "План развития" или "дорожная карта" |
| critical / nice to have | "Критичное / желательное" |

### Полнота текста

**Каждый буллет должен быть ПОЛНЫМ предложением или развёрнутой фразой.**

❌ **ЗАПРЕЩЕНО** (слишком кратко):
- "Рост продаж"
- "Новые клиенты"
- "Снижение затрат"

✅ **ПРАВИЛЬНО** (развёрнуто):
- "Рост продаж на 15% за счёт расширения в регионы"
- "Привлечено 42 новых клиента через digital-каналы"
- "Снижение операционных затрат на 8M₽ благодаря автоматизации"

**МИНИМАЛЬНЫЕ ТРЕБОВАНИЯ:**
- Заголовок слайда: **3-5 слов** (action title = вывод. Тест Маккинзи: при чтении только заголовков всех слайдов подряд должна складываться связная история)
- Подзаголовок колонки: 4-8 слов (краткий action title)
- Буллет в контенте: **минимум 8 слов** (полное предложение)
- Факт в sidebar: 6-12 слов (с цифрой или источником)

**ПРАВИЛА СТРУКТУРЫ ПРЕЗЕНТАЦИИ (SOSTAC):**
Каждая презентация для первого лица строится по SOSTAC:
1. Situation Analysis → анализ текущей ситуации (факты, данные)
2. Objectives → цели и задачи
3. Strategy → стратегия достижения
4. Tactics → тактические шаги
5. Action Plan → конкретный план действий
6. Control → методы контроля и корректировки

**SCQA НА КАЖДОМ СЛАЙДЕ (не только на типе scqa):**
- S = факты, один главный график (без оценочных суждений)
- C = почему это заслуживает внимания (**самый важный элемент**)
- Q = инструментарий для поиска ответа
- A = action title в заголовке (3-5 слов)

**ПРАВИЛО ПОСЫЛОК (BPM):**
Посылки на слайде должны быть из разных методов data mining (BPM): интервью, опросы, база данных, тайный покупатель и т.д. Минимум: количество посылок / 2 = количество разных BPM. Недопустим слайд, где все выводы основаны только на интервью.

**ЗАПРЕТЫ (обучение Балахнина 21.03.2026):**
- Слайды-перебивки (divider) строжайше запрещены
- Энциклопедические слайды (обзоры рынков, сравнения) — только в аппендикс
- Смешение стратегических, тактических и операционных шагов на одном слайде запрещено
- Посылочный график на месте вывода запрещён — вывод всегда текстом в заголовке
- Где можно показать данные одним графиком, два графика запрещены

### Сохранение содержания

**Если в источнике 5 аргументов — ВСЕ 5 должны попасть на слайд.**

❌ **ЗАПРЕЩЕНО**:
- Выбрасывать контент, чтобы "уместить в макет"
- Обобщать 3 аргумента в один
- Сокращать список "для красоты"

✅ **ПРАВИЛЬНО**:
- Если не влезает в 3 колонки `scqa` → используйте `table` или `numbered_list`
- Если не влезает в `comparison` → используйте `numbered_list` или `flow_blocks`
- Если факты не влезают в sidebar → увеличьте sidebar до 40% или уберите его

**Алгоритм при нехватке места:**
1. Проверьте, правильно ли выбран тип слайда (см. Алгоритм выбора)
2. Если 5+ элементов в макете для 3 — выберите другой тип
3. Если контент не влезает — создайте 2 слайда вместо 1
4. Никогда не сокращайте контент ради макета!

### Примеры неправильного и правильного текста

| Элемент | ❌ Плохо | ✅ Хорошо |
|---------|----------|-----------|
| Заголовок | "Анализ продаж" | "Продажи упали на 15% из-за задержек доставки и оттока 8 ключевых клиентов" |
| Буллет | "Новые клиенты" | "Привлечено 42 новых B2B-клиента через контекстную рекламу (+28% к Q1)" |
| Факт | "Growth +15%" | "Рост выручки на 15% (Q1 vs Q4 2025)" |
| Вывод | "Действия" | "Требуется сократить срок доставки до 2 дней и запустить программу лояльности" |
| Термин | "Customer journey gap" | "Анализ пути клиента выявил разрыв на этапе онбординга" |

### Консалтинговый тон и стиль формулировок

**Слайдументы — это рекомендации, а не ультиматумы.** Консалтинговый подход предполагает мягкие, уважительные формулировки. Клиент принимает решения сам, мы предлагаем.

❌ **ЗАПРЕЩЁННЫЕ формулировки** (слишком категоричные):
- "Требует немедленной приоритизации" → ✅ "Рекомендуется переприоритизировать"
- "Критические расхождения" → ✅ "Выявлены значимые расхождения"
- "Критические потребности" → ✅ "Ключевые потребности"
- "Полностью отсутствуют" → ✅ "На данный момент не представлены в бэклоге"
- "Необходимо срочно" → ✅ "Рекомендуется в первую очередь"
- "Провал / недоработка / ошибка" → ✅ "Зона развития / возможность для улучшения"

✅ **ПРАВИЛЬНЫЙ тон** (мягкий консалтинговый):
- "Мы предлагаем рассмотреть..."
- "По результатам анализа рекомендуется..."
- "Целесообразно сфокусировать внимание на..."
- "Данные интервью указывают на возможность..."

### Правила цитирования качественных исследований

**Глубинные интервью — это качественное исследование.** Их нельзя использовать для экстраполяции на всю аудиторию.

❌ **ЗАПРЕЩЕНО** (экстраполяция):
- "70% клиентов предпочитают мессенджеры" (невалидно: 70% из 52 респондентов ≠ 70% всех клиентов)
- "Большинство клиентов считают..." (мы не знаем про большинство, только про выборку)

✅ **ПРАВИЛЬНО** (корректные формулировки):
- "Большинство респондентов отметили..."
- "Респонденты указывают на значимость..."
- "По данным интервью, значительная часть опрошенных..."
- "37 из 52 респондентов отметили, что..." (конкретные цифры по выборке — ок)
- "В ходе интервью неоднократно упоминалось..."

### Принцип «методология перед результатами»

**Сначала объясни метод, потом показывай выводы.** Если используется фреймворк (RICE, MECE, BCG, и т.д.), нужно:
1. Объяснить, что это за модель и зачем она выбрана
2. Показать формулу / критерии / шкалы оценки
3. Только после этого показывать результаты ранжирования

Нельзя: сразу показывать таблицу RICE без объяснения, что стоит за каждым числом.

### Проверка MECE при группировке

При разделении задач/инициатив на группы — обосновать, почему именно такое деление:
- **ME (Mutually Exclusive):** группы не пересекаются — каждая задача попадает ровно в одну группу
- **CE (Collectively Exhaustive):** группы покрывают весь объём — ни одна задача не выпала из классификации
- Если деление не строго MECE — явно указать это и объяснить принцип группировки

#### Стилевые антипаттерны

❌ **ЗАПРЕЩЕНО в тексте слайдов:**

- Стрелочные цепочки (→) — переформулировать: "затем", "после этого", "сначала …, затем …"

- Списки-заголовки в строке ("X: X улучшился") — переводить в нормальную прозу

### Аудит аргументации (12 дефектов)

Де-ИИ ловит языковые паттерны. Аудит аргументации ловит логические — утверждения, которые звучат складно, но при экспертной проверке не выдерживают критики. Полный каталог: `Notes/Concepts/Дефекты аргументации.md`.

**Зоны максимального соблазна в слайдументах:**
- **Action titles** — концентрация сильных утверждений. Каждый action title = кандидат на unqualified claim
- **Executive summary** — обобщения, расширение области вывода (scope creep)
- **SCQA-блок Complication** — подмена причинности корреляцией, тривиальные наблюдения как инсайты

**Экспресс-проверка action title (перед генерацией каждого слайда):**
1. **Тест фальсифицируемости:** «При каких условиях этот вывод неверен?» Если ответ находится быстро — добавить квалификатор или переформулировать
2. **Тест тривиальности:** «Удивит ли этот вывод человека с 3+ годами опыта в отрасли клиента?» Если нет — усилить или заменить
3. **Тест каузальности:** содержит ли action title конструкцию «X определяет Y», «X приводит к Y»? Если да — есть ли данные об интервенции или это корреляция?

**Частые дефекты в слайдументах:**
| Дефект | Пример на слайде | Как исправить |
|--------|-----------------|---------------|
| Unqualified claim | "Геоаналитика определяет успех локации" | "Состав окружения коррелирует с выручкой точки (R²=0.73)" |
| Trivial insight | "Разные локации дают разный трафик" | Убрать или показать неочевидный аспект |
| False equivalence | Сравнение двух точек разного формата как "при прочих равных" | Указать, сколько переменных различается |
| Scope creep | "Этот подход работает для любой сети" (на основе 3 кейсов) | "В проанализированных сетях (12 точек, Москва)" |
| Missing denominator | "Выручка выросла на 170 млн" | "Выручка выросла на 170 млн (8% от оборота группы)" |
| Methodology appeal | "Мы использовали SHAP-модель" как аргумент качества | Добавить метрику качества модели |

### Направляющая идея презентации

**Каждый слайдумент имеет одну направляющую идею** — тезис, который проходит через все слайды. При чтении только action titles подряд должна складываться связная история, ведущая к этому тезису.

**Перед созданием слайдумента — сформулировать направляющую идею в одном предложении.** Каждый слайд проверять: «двигает ли он направляющую идею?» Слайд-сирота (интересный, но не в русле основного аргумента) ослабляет презентацию — либо переосмыслить его связь с идеей, либо вынести в аппендикс.

### Мосты между секциями SOSTAC

Divider-слайды запрещены, но содержательные мосты между секциями обязательны. Мост = первый слайд новой секции, который объясняет:
1. Что мы уже знаем из предыдущей секции (1 предложение)
2. Какой вопрос остаётся (1 предложение)
3. Что эта секция добавит (action title)

Мост привязан к направляющей идее, а не просто «связка между темами». Пример плохого моста: «Далее рассмотрим тактику». Пример хорошего: «Стратегия определила три направления роста. Вопрос — какие конкретные действия запустить в первый квартал и в каком порядке».

### Контроль качества перед генерацией

Перед созданием JSON ответьте:
1. ✅ Все тексты на русском языке? (кроме устоявшихся терминов)
2. ✅ Каждый буллет — минимум 8 слов?
3. ✅ Все аргументы из источника попали на слайд?
4. ✅ Заголовок — это action title с выводом, а не тема?
5. ✅ Нет сокращений типа "рост", "проблема", "решение" без деталей?
6. ✅ Тон мягкий, консалтинговый? (нет "требует", "критически", "провал")
7. ✅ Данные качественных исследований не экстраполируются? (нет "X% клиентов" по интервью)
8. ✅ Методология объяснена до показа результатов?
9. ✅ Группировка обоснована по MECE или явно указан принцип деления?
10. ✅ Нет ИИ-лексики ("ландшафт", "свидетельство", "демонстрируя", "Кроме того")?
11. ✅ Нет стратегических клише без конкретики ("ядро", "хвост", "локомотив", "драйвер")?
12. ✅ Нет стрелочных цепочек (→) и конструкций "не только X, но и Y"?
13. ✅ Нет канцелярита ("В целях", "В рамках"), избыточных оговорок и общих концовок?
14. ✅ Англицизмы переведены или расшифрованы при первом упоминании?
15. ✅ Action titles прошли тест фальсифицируемости? (нет unqualified claims)
16. ✅ Каждый слайд двигает направляющую идею? (нет слайдов-сирот)
17. ✅ Мосты между секциями содержательные? (не «Далее рассмотрим…»)
