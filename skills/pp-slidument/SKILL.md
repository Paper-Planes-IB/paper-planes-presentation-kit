# PP Slidument Skill

Paper Planes consulting sliduments — dense analytical documents that are read without a speaker, in the style of McKinsey/BCG strategy decks.

---

## 0. КРИТИЧЕСКИЕ ПРАВИЛА (читать первым)

### Что такое слайдумент

Слайдумент ≠ презентация для выступления. Слайдумент = плотный аналитический документ в формате слайдов, который читается самостоятельно, без спикера. Аналог: McKinsey blue book, BCG strategy deck.

### ОБЯЗАТЕЛЬНО

1. **Плотность**: каждый контентный слайд содержит 1000–1500 символов текста. Это ~5-8 абзацев, таблица + комментарий, или 3 колонки с данными
2. **Визуализация**: каждый контентный слайд ОБЯЗАН содержать минимум один визуальный элемент — таблицу, график (SVG), карточки, диаграмму, матрицу, или bento-grid блоки. Текст без визуализации = ошибка. Если есть числовые данные — СТРОЙ ГРАФИК, а не пиши числа текстом. См. таблицу «Обязательные визуальные элементы» ниже
3. **Action titles**: заголовок = вывод с цифрой, НЕ тема. «Объём продаж вырос на 15%» — да. «Анализ продаж» — нет
4. **Мало слайдов, много контента**: типичная презентация на 50 страниц PDF = 15-20 слайдументов. НЕ 50 слайдов по 3 буллета
5. **Направление чтения: СЛЕВА НАПРАВО.** Контент на каждом слайде организован горизонтально — колонки, карточки в ряд, таблицы. НИКОГДА не строить слайд сверху вниз (вертикальный буллет-лист). Единственное исключение — строки внутри таблицы

### ЗАПРЕЩЕНО

| Анти-паттерн | Почему плохо | Как правильно |
|-------------|-------------|---------------|
| 30+ слайдов с 3 буллетами | Это PowerPoint-караоке, не аналитика | 12-20 плотных слайдументов |
| Текст без визуализации | Нечитаемо, не видно структуры | Таблица, карточки, или график на каждом слайде |
| Заголовок-тема («Конкуренты») | Не несёт информации | Action title: «Три конкурента контролируют 68% рынка» |
| Один буллет-лист на весь слайд | Пустой слайд | 2-3 колонки SCQA + таблица/карточки |
| Вертикальная раскладка (сверху вниз) | Не консалтинговый формат, теряется SCQA | Всегда слева направо: колонки, карточки в ряд |
| Слайды-«спасибо» и «вопросы?» | Пустая трата места | Заменить на Executive Summary или финальные рекомендации |
| Декоративные элементы | Отвлекают от данных | Только функциональная графика |
| Раздувание блока до полной деки | Один тип данных → 1-5 слайдов, не 20 | Определи режим: блок vs полная презентация |
| Числа в тексте без графика | Данные не считываются визуально | Любые числовые данные → SVG-график или диаграмма |

### Структура типичной презентации

```
1. Титульный слайд (G1)
2. Содержание (G3)
3. Разделитель: Аналитика (G2)
4-8. Контентные слайды аналитики (A1-A4, B1-B4, C1-C5)
9. Разделитель: Стратегия (G2)
10-14. Контентные слайды стратегии (D1-D6, E1-E5)
15. Ключевые выводы (E2)
16. Рекомендации / Roadmap (E1, E3)
```

Итого: 16 слайдов. НЕ 40.

### Режим: полная презентация vs отдельный блок

**КРИТИЧНО.** Перед началом работы определи масштаб запроса:

| Сигнал | Режим | Сколько слайдов |
|--------|-------|-----------------|
| «Сделай презентацию», «АТС», «стратегия» + много разных данных | **Полная презентация** | 12–20 слайдументов (титул + содержание + разделители + контент) |
| Один конкретный блок данных: интервью, опрос, конкуренты, CJM | **Отдельный блок** | 1–5 контентных слайдов, БЕЗ титула/содержания/разделителей |
| Несколько блоков, но не полная дека | **Набор блоков** | 3–10 слайдов, минимум навигации |

**Правило определения режима:** если пользователь передаёт данные одного типа (например, только результаты интервью, или только анализ конкурентов) — это **отдельный блок**. Не раздувать до полной деки. Один блок данных = 1–5 слайдов максимум.

**Примеры:**
- «Вот результаты 12 интервью, сделай слайды» → блок, 2–4 слайда (сводка + ключевые цитаты + выводы)
- «Вот таблица конкурентов» → блок, 1–3 слайда (матрица + комментарий)
- «Сделай АТС для Берёзки, вот все данные» → полная презентация, 15–20 слайдов

### Обязательные визуальные элементы

**Каждый контентный слайд ОБЯЗАН содержать хотя бы один из:**

| Элемент | Когда использовать | Реализация |
|---------|-------------------|------------|
| **Таблица** | Сравнения, критерии, скоринг, финансы | HTML `<table>` / python-pptx `Table` |
| **Столбчатая диаграмма** | Сравнение величин, доли рынка | HTML `<svg>` bar chart / python-pptx `BarChart` |
| **Круговая диаграмма** | Структура, доли (≤6 сегментов) | HTML `<svg>` pie/donut / python-pptx `PieChart` |
| **Линейный график** | Динамика, тренды во времени | HTML `<svg>` line chart / python-pptx `LineChart` |
| **Карточки (bento-grid)** | Сегменты, портреты, этапы CJM | HTML `<div>` cards / python-pptx shapes |
| **Матрица 2×2** | Позиционирование, приоритизация | HTML grid / python-pptx shapes |
| **Горизонтальный таймлайн** | Roadmap, этапы проекта | HTML flex / python-pptx shapes |
| **Horizontal bar** | Рейтинги, NPS, воронка | HTML `<svg>` / python-pptx `BarChart` |

**Если данные содержат числа — ОБЯЗАТЕЛЬНО визуализируй их как график или диаграмму, а не только как текст.** Числа в тексте без визуализации = упущенная возможность.

**Для Manus/HTML:** используй `<svg>` для графиков — рисуй `<rect>`, `<circle>`, `<line>`, `<path>` напрямую. Не полагайся на внешние библиотеки. Каждый SVG-график должен иметь оси, подписи, легенду.

## 1. МЕТОДОЛОГИЯ

### Core Principles

**SCQA Structure** — каждый контентный слайд читается слева → справо:
- Левая колонка: Situation (ситуация, предпосылки, текущее состояние)
- Центр: Complication (проблемы, факты, данные)
- Правая колонка: Answer (выводы, рекомендации, действия)

**Action Titles** — заголовок = вывод, не описание темы:
- WRONG: «Анализ продаж», «Итоги исследования»
- RIGHT: «Объём продаж вырос на 15% за счёт трёх категорий»
- Тест: прочитать только заголовки подряд → связная история с выводами

**MECE** — взаимоисключающие, совокупно полные элементы. Нет пересечений, нет пропусков.

**Пирамида Минто** — главная мысль в заголовке, поддерживающие аргументы ниже, детали в нижних уровнях.

**Триангуляция** — минимум 2 источника из разных категорий на каждый слайд.

**Ценность, а не деятельность** — фокус на том, что клиент получит, а не на том, что мы будем делать. Измеримые результаты, инициативы роста.

### Библиотека типов слайдов (33 типа, 7 категорий)

- Полный каталог типов с паттернами верстки → `references/slide_types.md`
- Гайд: как давать вводные для каждого типа слайда → `references/usage_guide.md`

| Кат. | Название | Примеры типов |
|------|----------|---------------|
| **A** | Исследования и сбор данных | Сводка интервью, Результаты опроса, Тайный покупатель, NPS/Лояльность |
| **B** | Рынок и конкуренты | Анализ конкурентов, Market Sizing, Porter/Барьеры, Тренды, PEST |
| **C** | Клиент и путь | CJM, Сегментация/Портрет, Unit-экономика, Воронка |
| **D** | Данные и аналитика | Декомпозиция, SWOT, ABC/BCG, Финпоказатели, Оргструктура, Бизнес-процессы |
| **E** | Стратегия и рекомендации | Позиционирование, Ассортимент, Ценообразование, Каналы, Продвижение, Roadmap, Скоринг, ROI |
| **F** | Брендинг | Бренд-платформа, Айдентика, Коммуникационная стратегия, Контент/SMM |
| **G** | Навигация | Титульный, Разделитель, Содержание, Методология, Команда, Приложения |

#### Decision Tree: выбор типа слайда

```
Фаза проекта?
├─ Аналитический этап
│  ├─ Есть данные интервью? → A1 Сводка интервью
│  ├─ Есть данные опроса? → A2 Результаты опроса
│  ├─ Есть mystery shopping? → A3 Тайный покупатель
│  ├─ Нужен анализ конкурентов? → B1 Анализ конкурентов
│  ├─ Нужен размер рынка? → B2 Market Sizing
│  └─ Нужна декомпозиция? → D2 Декомпозиция
├─ Стратегия
│  ├─ Позиционирование? → D1
│  ├─ Ценообразование? → E3 (через Roadmap)
│  ├─ Каналы? → E4 (через Roadmap)
│  └─ План действий? → E1 Рекомендации
└─ Брендинг → F1–F4
```

### Pre-Send Checklist

- [ ] Заголовок — action title (вывод с цифрой)
- [ ] SCQA слева направо
- [ ] Минимум 2 источника (триангуляция)
- [ ] MECE соблюдён
- [ ] Каждый контентный слайд: таблица/график/карточки
- [ ] 1000+ символов на контентный слайд
- [ ] Корпоративные цвета Paper Planes
- [ ] Нет шрифтов < 10pt
- [ ] Нет теней, градиентов, декоративных элементов

## 2. ВИЗУАЛЬНЫЙ СТИЛЬ

### Эстетика
Tech-минимализм с высокой плотностью информации. Чисто, остро, авторитетно. Ощущение премиального финансового отчёта.
**Нет теней, нет градиентов, нет glow** — только плоские элементы.

### Типографика
- Шрифт: **Inter** (корпоративный). **Arial** — fallback только для python-pptx
- Межстрочный интервал: 1.0 (одинарный)
- Межабзацный: минимальный (1-2pt)
- Выравнивание: LEFT всегда (кроме однобуквенных кодов и центральных лейблов)

#### Иерархия размеров шрифтов

| Элемент | Размер | Когда |
|---------|--------|-------|
| Заголовок разделителя | **44pt** bold | Слайды-разделители |
| Заголовок титульного | **36-40pt** | Первый слайд |
| Заголовок слайда (короткий) | **24pt** | До 60 символов |
| Заголовок слайда (длинный) | **18pt** | 60-150 символов |
| Подзаголовки секций | **14-15.5pt** bold | Внутри слайда |
| Основной текст | **12-14pt** | Описания, буллеты, абзацы |
| Текст в таблицах | **10-12pt** | Ячейки таблиц |
| Мелкие подписи | **10pt** | Источники, метки. МИНИМУМ |
| Крупные акцентные числа | **39.5pt** bold | Ключевые метрики (20%, 450+) |

**КРИТИЧНО**: основной текст = 12pt. Никогда не меньше 10pt. Это не опечатка.

### Палитра и её применение

**КРИТИЧНО: Основной фон слайдов — строго белый (#FFFFFF) для ВСЕХ слайдов без исключения.** Никаких серых, голубых или иных фонов. Белый фон = базовый принцип.

**Основная палитра (обязательная):**

| Элемент | Цвет | HEX | RGB |
|---------|------|-----|-----|
| Фон ВСЕХ слайдов | WHITE | #FFFFFF | 255, 255, 255 |
| Основной текст, заголовки | DARK | #181D27 | 24, 29, 39 |
| Акцент, выделения, кнопки | CORAL | #FF5850 | 255, 88, 80 |
| Лёгкий акцентный фон | CORAL_LIGHT | #FFEBEA | 255, 235, 234 |
| Вторичный текст | MUTED | #717680 | 113, 118, 128 |
| Дополнительный текст | STEEL | #414651 | 65, 70, 81 |
| Фон карточек/блоков внутри слайда | SOFT | #F7F8FA | 247, 248, 250 |
| Второй мягкий фон | SOFT_2 | #EEF1F5 | 238, 241, 245 |
| Границы, разделители | GRAY_BORDER | #D5D7DA | 213, 215, 218 |
| Чередование строк таблиц | CELL_ALT_BG | #F7F8FA | 247, 248, 250 |

**Дополнительные цвета (ТОЛЬКО по отдельному запросу):**

| Элемент | HEX | Когда |
|---------|-----|-------|
| Светло-зелёный | #B8DAB3 | Рост, позитивные результаты, вторичные данные |
| Светло-зелёный фон | #EEF7EC | Подтверждённое или положительное состояние |
| Светло-жёлтый фон | #FFF5D8 | Зона внимания или ожидания |
| Светло-голубой фон | #E6EEF2 | Информационный блок |

**Правила применения цветов:**

1. **Фон слайда** — ТОЛЬКО белый (#FFFFFF). Никаких исключений
2. **Основной текст** — тёмно-серый (#181D27). Никогда не чёрный (#000000)
3. **Акценты** — красный (#FF5850) для выделений, ключевых элементов, некоторых кнопок
4. **Карточки внутри слайда** — белый (#FFFFFF) фон с серой рамкой (#D5D7DA). Внутренние подсекции — #F7F8FA или #EEF1F5
5. **Никаких дополнительных цветов** без специального разрешения

**Правила для таблиц:**
- Заголовки таблиц: тёмный фон (#181D27), белый текст
- Строки: чередование белый / #F7F8FA
- Границы: тонкие (#D5D7DA)

**Правила для графиков/диаграмм:**
- Основные данные: тёмный (#181D27) или коралловый (#FF5850); мягкий голубой (#E6EEF2) используется только как фон
- Вторичные данные / рост: зелёный (#B8DAB3)
- Акцент / выделение: коралловый (#FF5850)

### UI-элементы

**Маркеры списков:**
- Основные пункты: красные квадраты ■ (#FF5850), w-2 h-2
- Подпункты: красные точки • (#FF5850), w-1 h-1

**Разделительные линии:**
- Тонкие (1px / 0.5pt) линии светло-серого цвета (#D5D7DA)
- Акцентная линия: тонкая красная (#FF5850) полоса под заголовками разделов

**Бейджи/метки:**
- Текущие проекты / статус: чёрный фон (#181D27), белый текст, скруглённые углы
- Будущие проекты / акцент: красный фон (#FF5850), белый текст, скруглённые углы

**Карточки и блоки (bento-grid):**
- Белый фон (#FFFFFF) с тонкой серой рамкой (#D5D7DA)
- Внутренние секции: фон #F7F8FA
- Скруглённые углы (rounded-lg)
- Каждая карточка = один смысловой блок

**Иконки:** минималистичные одноцветные (белые на цветном фоне, чёрные на белом). Без декоративных элементов.

**Нумерация этапов процесса:**
- Основные этапы: красные (#FF5850) квадраты с белыми цифрами
- Подэтапы: чёрные (#181D27) квадраты с белыми цифрами

**Нумерация результатов:** формат 01, 02, 03 на чёрном (#181D27) фоне с белым текстом

### Передовые практики консалтинговых презентаций

**Контент:**
- Значение вместо деятельности: фокус на том, что клиент получит, а не на том, что мы будем делать
- Измеримые результаты: конкретные, но обобщённые цифры и показатели успеха
- Инициативы роста: формулировка через возможности роста, не гарантии
- Стратегическое мышление: демонстрация глубокого понимания бизнеса клиента

**Визуализация:**
- Последовательное повествование: логическое развитие идей от слайда к слайду
- Контрастные акценты: красные (#FF5850) линии под заголовками для выделения ключевых разделов
- Пространство вокруг элементов: достаточно воздуха для лёгкости восприятия
- Визуальное кодирование: коралловый = высокий приоритет, #181D27 = основное содержание, #F7F8FA = фон вспомогательных блоков, #D5D7DA = границы

**Кейс-стади и референсы:**
- Карточная структура: 3 колонки с чётким визуальным разделением
- Структурированность: заголовок, подзаголовок с акцентной линией, ключевые работы, результаты
- Нумерация результатов: 01, 02 на чёрном фоне
- Акцент на бизнес-результаты: измеримые показатели успеха

### Графические стандарты
- Тонкие рамки таблиц (0.3-0.75pt), цвет #D5D7DA
- **НИКАКИХ теней, градиентов, свечений** — только плоские элементы
- Шевроны (►) в CORAL между аналитическими секциями
- Акцентная полоска CORAL на левом краю ключевых ячеек
- Harvey Balls для индикаторов зрелости/полноты

## 3. ПАТТЕРНЫ РАСКЛАДКИ (tool-agnostic)

Каждый контентный слайд должен соответствовать одному из этих паттернов. **Текст-only = ошибка.**

### Паттерн 1: Таблица + комментарий
Используется для: конкурентный анализ, финпоказатели, скоринг, ассортимент.
```
┌─────────────────────────────────────────────┐
│ Action title: "Три конкурента ..."          │
├─────────────────────────────────────────────┤
│ ┌──────────────────────────────────────┐    │
│ │  Таблица 5-10 строк × 5-8 столбцов  │    │
│ │  Заголовки: тёмный фон, белый текст  │    │
│ │  Чередование строк: белый / #F7F8FA  │    │
│ │  Акцентная полоска CORAL слева       │    │
│ └──────────────────────────────────────┘    │
│ Комментарий: 2-3 предложения с выводом     │
│ Источник: 10pt, серый текст                │
└─────────────────────────────────────────────┘
```

### Паттерн 2: Три колонки SCQA
Используется для: сводка интервью, ключевые выводы, рекомендации.
```
┌─────────────────────────────────────────────┐
│ Action title                                │
├──────────────┬──────────────┬───────────────┤
│ /Ситуация    │ /Проблема    │ /Решение      │
│              │              │               │
│ 3-4 факта    │ 3-4 факта    │ 3-4 рекоменд. │
│ с цифрами    │ с цифрами    │ с эффектом    │
│              │              │               │
├──────────────┴──────────────┴───────────────┤
│ Источники: интервью N=15, опрос N=500       │
```

### Editable PPTX production mode

Use this mode when the output must be a real PowerPoint file with editable text, tables, cards and diagrams.

Mandatory sequence:

- file opens in PowerPoint without warnings.

### Two-Layer Adaptive Sizing

1. **Formula** — `calc_adaptive_size()` computes approximate font size
2. **Safety net** — `normAutofit` on every content shape (PowerPoint shrinks-to-fit)

### Calibrated Constants

| Parameter | Value | Rationale |
|-----------|-------|-----------|
| `ARIAL_CHAR_WIDTH` | **0.58** | Cyrillic average. Ш/Щ/Ж/Ю are 0.66-0.73 |
| `TARGET_FILL` | **0.78** | 22% safety margin for word-wrap waste |
| `LINE_HEIGHT_RATIO` | **1.15** | For formula only (NOT for setting line spacing!) |
| `bullet_extra` | **3.0 pt/item** | space_before + space_after + engine overhead |
| `MIN_PT` | **10.0** | Hard minimum readability floor |
| `MAX_PT` | **14.0** | Hard max for body text |

### Adaptive Sizing Formula

```python
def calc_adaptive_size(cw, ch, total_chars, margin_l, margin_r, margin_t, margin_b,
                       n_items=0, target_fill=0.78, min_pt=10.0, max_pt=14.0):
    aw = (cw - margin_l - margin_r) * 72
    ah = (ch - margin_t - margin_b) * 72
    bullet_extra = max(0, (n_items - 1)) * 3.0
    th = ah * target_fill - bullet_extra
    denom = total_chars * 0.58 * 1.15
    s = sqrt(th * aw / denom)
    s = clamp(s, min_pt, max_pt)
    s = round(s * 4) / 4
    return s
```

### Shadow Removal (mandatory)

```python
def remove_all_shadows(slide):
    for shape in slide.shapes:
        sp = shape._element
        for effectLst in sp.findall('.//' + qn('a:effectLst')):
            effectLst.getparent().remove(effectLst)
        spPr = sp.find(qn('p:spPr'))
        if spPr is None:
            spPr = sp.find('.//' + qn('a:spPr'))
        if spPr is not None:
            for eff in spPr.findall(qn('a:effectLst')):
                spPr.remove(eff)
            etree.SubElement(spPr, qn('a:effectLst'))
    for tbl in slide.shapes:
        if tbl.has_table:
            for effectLst in tbl._element.findall('.//' + qn('a:effectLst')):
                effectLst.getparent().remove(effectLst)
```

### Hard Rules (python-pptx)

1. H-align: ALWAYS LEFT (exceptions: single-letter codes)
2. V-anchor: ALWAYS TOP (exception: thin strips ≤ 0.22")
3. Line spacing: ALWAYS single (1.0). NEVER set explicit Pt()
4. No shadows: call remove_all_shadows() before save
5. Content MUST FIT within shape boundaries
6. NEVER add slides to existing PPTX — clear-and-reuse only

```python
def clear_slide(slide):
```

## 5. COMMON MISTAKES

| Ошибка | Исправление |
|--------|-------------|
| 30+ слайдов по 3 буллета | 12-20 плотных слайдументов по 1000+ символов |
| Текстовые слайды без визуализации | Каждый слайд: таблица, карточки, график или матрица |
| Заголовок-тема («Конкуренты») | Action title: «Три конкурента контролируют 68% рынка» |
| Основной текст 7-9pt | Минимум 12pt. Абсолютный минимум 10pt |
| Один источник | Минимум 2 (триангуляция) |
| Выводы внизу | Выводы справа (SCQA → Answer column) |
| Тени на фигурах | Убрать все тени. Плоский стиль |
| Слайд «Спасибо за внимание» | Заменить на Executive Summary |
| Пустые декоративные слайды | Каждый слайд несёт аналитическую ценность |
