# Overlay: Paper Planes / Балахнин фильтр для английских маркетинговых скиллов

## Зачем нужен

27 скиллов из `coreyhaines31/marketingskills` написаны под западный B2C/SaaS. Их дефолтный стиль — типичный «AI-маркетинговый» английский: power words, «not just X but Y», hero-bullet формат, «unlock your potential», «transform your business», эмодзи 🚀💡, listicles по 5/7 пунктов. Всё это прямо нарушает редполитику Paper Planes и Voice Profile Балахнина.

Overlay подключается автоматически. Алгоритм: **выбрать регистр → сгенерить → прогнать по фильтрам → переписать спорное → отдать**.

## Шаг 1. Выбрать регистр голоса (ДО генерации)

| Контекст | Регистр | Источник |
|---|---|---|
| КП, методичка, презентация клиенту, Excel, статья на media.paper-planes.ru | **1 (Профессорский)** только | Voice Profile §3 |
| TG-канал Балахнина, авторская колонка | **1, 2 или 3** по ситуации | Voice Profile §3 |
| Контент клиента (не PP) — оставить тон бренда клиента, но прогнать через 24 паттерна | Спросить тон у пользователя | — |

**По умолчанию:** Регистр 1, от лица агентства («мы», «наше агентство»). Не «я».

## Шаг 1.5. Коммерческие ворота PP (то, чего overlay раньше не закрывал)

Overlay чинил язык, но пропускал архитектуру: контент уходил в операционку и generic мимо
собственника и продажи. Для контента PP / Б&П прогнать по воротам ДО и ПОСЛЕ генерации
(полная рамка — `Контент/_работа-над-ошибками-контента/00_рамка_10_ворот.md`):

- **G1 Читатель — собственник / CEO / руководитель**, решающий о проекте, не исполнитель и
  не «CEO-минус-4». Операционная деталь только как доказательство управленческой боли.
- **G2 Downstream:** симптом собственника → маршрут витрины 02.4 → доказательство-кейс →
  следующий шаг → сигнал (заявка/КП/win-loss/qualified attention).
- **G3 Витрина 02.4 — ворота:** нет привязки к продуктовому маршруту — в harvest.
- **G7 Рельса РГ:** РГ-1 (B2B/пром/CRM/экспертные продажи) или РГ-2 (медицина/hospitality/
  SaaS/PSF); прогрев просевших и приоритетных продуктов.

**Failsafe (важно):** overlay — языковой фильтр, он НЕ переделывает архитектуру upstream-
скилла. Если исходный скилл (`content-strategy`, `social-content`, `copywriting`) выдал
контент без owner-аудитории, без маршрута витрины или мимо sales gap — это не чинится
переписыванием фраз. Флагнуть пользователю: «нужна правка upstream-скилла / выбора темы»,
а не маскировать дефект красивым языком.

## Шаг 2. Что вырезать из выхода английских скиллов

Английские скиллы по умолчанию пушат эти конструкции — заменять до того, как покажете пользователю:

### Конструкции уровня предложения

| Что предлагает скилл | Чем заменить (PP) |
|---|---|
| «Transform your business» / «Unlock potential» | Конкретный «до → после» с цифрой |
| «Save time on your workflow» | «Сократить недельную отчётность с 4 ч до 15 мин» |
| «Game-changing» / «revolutionary» / «next-gen» | Назвать конкретное изменение |
| «Not just X, but Y» / «It's not X, it's Y» | **Запрещено всегда.** Сказать тезис прямо |
| «Discover how to…» как H1 | Зеркальное открытие — переписать со сцены/цифры |
| «In today's fast-paced world…» | Удалить, начать с конкретного факта |
| «Robust / seamless / cutting-edge / leverage» | «Сильный», «прямой», «использовать» |
| «Drive growth / fuel innovation» | «Растить выручку», «строить продукты» |
| Эмодзи в маркерах списка 🚀💡⚡✨ | Убрать. Максимум 1 на пост и только в Регистре 2 |
| Hero-формат «✓ Feature → Benefit» (стрелка) | Развернуть в полноценную фразу. Стрелки `→` запрещены |
| CTA «Get started today» / «Join the revolution» | Конкретный шаг с глаголом действия и сроком |

### Структурные

- **Listicle на 3 / 5 / 7 / 10** → использовать реальное число (4, 6, 11). Дефолтное «Top 5» — маркер ИИ
- **Социальное доказательство через перечисление медиа** («as seen in NYT, BBC, FT») → конкретная цитата из одного источника с годом
- **Power words в каждом пункте** («amazing», «incredible», «proven», «trusted») — снять
- **Заголовки в Title Case** — в русском не используем. Только обычная орфография

### Лексика-замена (дефолт английских скиллов → русский PP)

| EN | RU |
|---|---|
| SKU | товарная позиция |
| MVP | пилот |
| ROI | возврат на вложения / окупаемость |
| A/B test | сравнительный тест |
| BCG matrix | матрица роста и доли |
| funnel | воронка (можно оставить) |
| lead | лид (если клиент так говорит) или «контакт» |
| churn | отток |
| onboarding | внедрение / первое касание |
| no-show | неявка |
| roadmap | дорожная карта / план |
| must-have / nice-to-have | обязательное / желательное |
| TCO | совокупная стоимость владения |

Полный список — в `ai_patterns_check.md`, раздел «Прочие англицизмы».

## Шаг 3. Что добавить (фирменные приёмы PP / Балахнина)

Английские скиллы этого **не делают сами** — добавлять руками:

1. **Пример из не-бизнес-домена** (главное правило Voice Profile §7.1) — каждый методологический текст должен иметь хотя бы один. Банк доменов: наука, быт/производство, страны, литература/кино, спорт, армия, медицина, кулинария, инженерия. Пример: Hilton — белый кусочек ткани для стирщиц; Япония — ownership улицы; Деминг про вариативность; Локхарт «Плач математика».
2. **Цитата теоретика с авторским глоссом** — формат: «Как говорил X, важнейшее свойство Y — Z. Он определял его как…». Каталог авторов: Локхарт, Деминг, Бранден, Жеглов, Баум/Волков, Вебер, Бауэр, Майстер, Тиль.
3. **Личный эксперимент / конкретика про агентство** — «За 3 часа собрал систему» бьёт «Мы считаем, что возможно».
4. **Фирменные термины PP** к месту: формула прибыли, 6 рычагов роста, 4 стратегии роста выручки, архитектура продаж (PreSell / Sell / Cross-Sell / Up-Sell / Re-Sell), JTBD, EST-спецификации, Revenue Management, ЦКП, Full Kit, КЭВ, 4R, «гений места», зона извлечения прибыли.
5. **Если кейс — структура «Имеем / Запрос / Первая гипотеза / Реальная проблема / Что сделали / Вывод»** (Voice Profile §5, Структура 5).
6. **Зачины из каталога** (Voice Profile §4) — никогда не открывать пересказом темы. 8 шаблонов: «Знакомая картина: …», эмоциональное междометие, полемический ввод, заголовок-утверждение без глагола, история-кейс, реакция на дискуссию, благодарность за опрос, провокационный вопрос.

## Шаг 4. Финальный smell-test (7 вопросов перед отдачей)

После того как переписали — обязательно прогнать:

1. Открытие не пересказывает тему?
2. Есть минимум один пример из не-бизнес-домена (если методология)?
3. Каждое утверждение с цифрой, фактом или конкретным кейсом?
4. Нет ни одной конструкции «не X, а Y»?
5. Нет слов-маркеров ИИ (ключевой, бесшовный, ландшафт, при этом, тем не менее, способствовать, задействовать, резонировать, трансформирующий)?
6. Концовка не резюмирует — даёт взгляд вперёд, CTA с конкретикой или крылатую фразу?
7. Если прочитать вслух — звучит как живой голос, а не как брошюра?
8. Адресат — собственник/руководитель, решающий о проекте, и видна управленческая боль (не операционка ради операционки)?
9. Есть привязка к маршруту витрины 02.4 и понятный downstream-сигнал (заявка/КП/qualified attention)?

Если «нет» по 1–7 — возвращаемся на Шаг 2 (язык). Если «нет» по 8–9 — это архитектура, см. failsafe в Шаге 1.5: править upstream-скилл, а не фразы.

## Что показать пользователю

После прогона выдать **три блока:**

1. **Финальный текст** (готовый, в выбранном регистре)
2. **Список правок** (5–10 буллетов: что убрано / переписано и почему — ссылка на номер паттерна или раздел Voice Profile)
3. **Что уточнить у автора** (3–7 вопросов: источники, цифры, конкретные кейсы для замены абстракций)

## Когда НЕ применять overlay

- Технические артефакты: код, JSON-конфиги, schema-markup, аналитические трекинг-планы (там стиль не релевантен)
- Внутренние черновики и брейнштормы по запросу пользователя
- Прямые цитаты из первоисточников
