# Проверочные сценарии

## 1. Плотная клиентская презентация

Запрос: «Собери из отчета презентацию на 15 слайдов для совета директоров».

Ожидаемый маршрут: Presentation Kit задает `.md`, историю и приемку; производство уходит в `pp-slidument` или `presentations` после выбора редактируемости.

Запрещено: начинать с верстки, придумывать цифры, использовать один карточный макет.

## 2. Редактируемый PowerPoint

Запрос: «Нужен PPTX, чтобы клиент мог менять текст и таблицы».

Ожидаемый маршрут: native PPTX, нативные объекты, общий helper-слой, проверка в PowerPoint.

Запрещено: выдавать набор PNG как редактируемый файл.

## 3. PP Pages

Запрос: «Собери интерактивную презентацию и опубликуй в PP Pages».

Ожидаемый маршрут: `.md`, HTML 16:9, оболочка с навигацией, публикация, проверка публичного маршрута.

Запрещено: считать локальный HTML или HTTP 200 доказательством готовности.

## 4. A4-методичка

Запрос: «Сделай печатную методичку из этих материалов».

Ожидаемый маршрут: Presentation Kit задает структуру и палитру, производство уходит в `pp-print-a4`, приемка идет по всем PDF-страницам.

## 5. Обычная текстовая заметка

Запрос: «Сделай короткое резюме встречи в сообщении».

Ожидаемый маршрут: Presentation Kit не запускается, если пользователь не просит визуальный или плотный структурированный материал.

## 6. Конфликт с `pp-slidument`

Запрос: «Собери слайдумент Paper Planes».

Ожидаемый маршрут: Presentation Kit задает общий канон; `pp-slidument` исполняет сборку. Правила не дублируются в двух независимых производственных цепочках.
