# Quick start: HTML-презентация Paper Planes

Эта инструкция для тех, кто впервые собирает HTML-презентацию в стиле Paper Planes.

Главное: сначала пишем содержание, потом верстаем. HTML появляется только после того, как понятны история, источники и роль каждого слайда.

## 1. Откройте репозиторий

Репозиторий: https://github.com/ntokaeva/paper-planes-presentation-kit

Внутри важны четыре места:

- `templates/deck-content-template.md` — шаблон для текста презентации;
- `reference/visual-style-guide.md` — цвета и визуальные правила;
- `agents/pp-text-critic.md` — проверка текста;
- `agents/pp-slide-critic.md` — проверка слайдов.

Если вы не знаете, с чего начать, начинайте с `templates/deck-content-template.md`.

## 2. Создайте содержательный `.md`

Скопируйте `templates/deck-content-template.md` в папку своего проекта и переименуйте файл по смыслу, например:

```text
elevel-decision-deck-content.md
```

Заполните паспорт:

- проект;
- автор;
- версия;
- дата;
- аудитория;
- какое решение должна поддержать презентация;
- главный источник данных;
- ограничения пакета.

Не переходите к HTML, пока паспорт пустой.

## 3. Соберите историю презентации

В начале файла заполните четыре блока:

1. Ситуация — что аудитория уже знает.
2. Осложнение — почему нужно принять решение.
3. Вопрос — какой управленческий вопрос закрывает презентация.
4. Ответ — какой вывод или варианты выносите на обсуждение.

Это скелет презентации. Если эти четыре блока не заполнены, слайды будут случайным набором карточек.

## 4. Заполните каждый слайд

Для каждого слайда заполните отдельный блок.

Минимум для каждого слайда:

- рабочий заголовок-вывод;
- роль в истории;
- тезис;
- что должен понять или решить читатель;
- факты и цифры;
- источник каждого важного утверждения;
- интерпретация;
- ограничения и неизвестные;
- тип визуала;
- статус.

Плохой заголовок: `Анализ рынка`.

Хороший заголовок: `Рынок растёт за счёт двух сегментов, но маржинальность смещается в нижний ценовой слой`.

Заголовок должен сообщать вывод, а не тему.

## 5. Проверьте источники

У каждой цифры и важного утверждения должен быть источник.

Нормальный источник выглядит так:

```text
Источник: интервью с коммерческим директором, 2026-07-03, блок "каналы продаж"
Источник: файл sales_export.xlsx, лист "2025", строки 12-48
Источник: презентация клиента, слайд 14
```

Плохой источник:

```text
Источник: клиент сказал
Источник: аналитика
Источник: интернет
```

Если источник нельзя найти повторно, утверждение нельзя ставить в слайд как факт.

## 6. Выберите тип визуала

Форма слайда выбирается по задаче.

| Задача | Что использовать |
|---|---|
| Сравнить варианты | таблица или матрица |
| Показать путь | маршрут или таймлайн |
| Показать причину и следствие | схема связи |
| Показать структуру компании | оргмодель |
| Показать приоритеты | матрица решений |
| Показать динамику | график |
| Показать список действий | roadmap или чек-лист |

Один карточный макет нельзя использовать для всей презентации. Разные задачи требуют разной формы.

## 7. Прогоните текстовую проверку

До верстки прогоните содержательный `.md` через `agents/pp-text-critic.md`.

Проверяется:

- язык;
- точность формулировок;
- англицизмы;
- AI-паттерны;
- слабые переходы;
- внутренние слова, непонятные клиенту.

Исправления вносите в `.md`, а не в HTML после генерации.

## 8. Сверстайте HTML

HTML собирается из готового `.md`.

Базовые правила:

- формат 16:9;
- белый фон слайда;
- читаемый текст;
- логотип, номер страницы и служебные зоны стоят одинаково;
- цвет используется по смыслу, а не ради украшения;
- источники видны и читаются;
- текст не вылезает за блоки.

Каноническая палитра лежит в `reference/visual-style-guide.md`.

Основные цвета:

| Роль | HEX |
|---|---|
| Основной текст | `#181D27` |
| Вторичный текст | `#414651` |
| Служебный текст | `#717680` |
| Линии | `#D5D7DA` |
| Мягкий фон | `#F7F8FA` |
| Фон страницы | `#F5F5F5` |
| Белый | `#FFFFFF` |
| Акцент | `#FF5850` |
| Мягкий акцент | `#FFEBEA` |

## 9. Проверьте реальный рендер

Откройте HTML в размере 1600 x 900 или 1280 x 720.

Проверьте каждый слайд:

- текст не обрезан;
- нет случайных пустот;
- заголовок и визуал говорят об одном выводе;
- источники читаются;
- номера и логотип не прыгают;
- соседние слайды не выглядят как копии друг друга;
- цвета используются одинаково по всей презентации.

Если есть контактный лист со всеми слайдами, проверьте его целиком.

## 10. Прогоните слайдовую проверку

После HTML-верстки используйте `agents/pp-slide-critic.md`.

Проверяется:

- заголовки-выводы;
- источники;
- плотность;
- читаемость;
- шрифты;
- таблицы;
- тени и лишние эффекты;
- единство всей презентации.

После проверки исправьте HTML и снова просмотрите рендер.

## 11. Подготовьте итоговые файлы

Минимальный комплект для передачи:

- содержательный `.md`;
- HTML-презентация;
- список источников;
- короткий комментарий, что проверено;
- если нужен PowerPoint — PPTX-экспорт.

Если презентация публикуется в PP Pages, после публикации откройте публичную ссылку и проверьте всю страницу.

## 12. Чего нельзя делать

- Нельзя начинать с выбора карточек, цветов и декоративных элементов.
- Нельзя верстать HTML без содержательного `.md`.
- Нельзя оставлять цифры без источников.
- Нельзя исправлять плохой текст JavaScript-заменами после рендера.
- Нельзя использовать один макет для всех слайдов.
- Нельзя отдавать презентацию без `pp-text-critic` и `pp-slide-critic`.

## Быстрый чек-лист перед сдачей

- [ ] Есть содержательный `.md`.
- [ ] Заполнены ситуация, осложнение, вопрос, ответ.
- [ ] У каждого слайда есть заголовок-вывод.
- [ ] У каждой цифры есть источник.
- [ ] Тип визуала выбран по задаче.
- [ ] Текст прошёл `pp-text-critic`.
- [ ] HTML открыт и проверен целиком.
- [ ] Слайды прошли `pp-slide-critic`.
- [ ] Итоговая версия собрана из актуального `.md`.
