# Нативный редактируемый PPTX в Paper Planes

Это production-путь для случаев, когда клиенту или команде нужен `.pptx`, который можно редактировать в PowerPoint: менять текст, двигать блоки, править таблицы, переиспользовать отдельные слайды.

## Когда выбирать этот путь

Используйте нативный PPTX, если:

- файл будет жить после встречи и редактироваться командой;
- клиенту нужно менять формулировки внутри PowerPoint;
- слайды войдут в большую клиентскую деку;
- нужны таблицы, карточки, схемы и простые графики как нативные объекты;
- HTML-версия нужна как витрина или референс, но итогом является PowerPoint.

Растровый PPTX из PNG подходит для быстрого согласования визуала. Нативный PPTX подходит для рабочей передачи.

## Каноническая цепочка

```text
content.md
validation
storyline / slide intents
native-pptx builder
render / visual QA
pp-text-critic
pp-slide-critic
handoff
```

Сборка не начинается с пустого шаблона. Сначала должен быть содержательный `.md`: цель, аудитория, история, заголовки-выводы, тезисы, факты, источники, ограничения, тип визуала.

## Базовые параметры

- Размер: 16:9, `13.333 × 7.5 in`.
- Пустой layout: `prs.slide_layouts[6]`.
- Основной фон: `#FFFFFF`.
- Основной текст: `#181D27`.
- Вторичный текст: `#414651` или `#717680`.
- Линии: `#D5D7DA`.
- Мягкие фоны: `#F7F8FA`, `#EEF1F5`.
- Акцент: `#FF5850`, мягкий акцент `#FFEBEA`.
- Шрифты: Inter при наличии; Arial как безопасный fallback для PowerPoint.
- Минимальный размер текста: 10 pt. Основной текст обычно 11–14 pt.

## Helper-слой обязателен

Нативный PPTX нельзя собирать как набор разрозненных `shape` без общего слоя функций. Минимальный builder должен иметь:

- `add_title(slide, text, code=None)` — единый заголовок-вывод;
- `add_footer(slide, source, page_no=None, logo=True)` — единый подвал;
- `add_card(slide, x, y, w, h, title, body, accent=None)` — карточка с рамкой и опциональной акцентной полосой;
- `add_chip(slide, text, tone="default")` — бейдж/чип;
- `add_table(slide, rows, widths, header=True)` — таблица с единым стилем;
- `add_bar_chart(...)` / `add_matrix(...)` / `add_timeline(...)` — типовые визуальные элементы;
- `remove_all_shadows(slide)` — обязательный проход перед сохранением;
- `apply_text_fit(shape, min_pt=10, max_pt=14)` — защита от обрезания текста;
- `clear_slide(slide)` — переиспользование слайдов без накопления мусора.

## Правила для объектов PowerPoint

1. Текстовые блоки выравниваются по левому краю.
2. Вертикальная привязка текста — top.
3. Межстрочный интервал — одинарный; не задавать агрессивные `Pt()`-интервалы.
4. Тени, glow, градиенты и декоративные эффекты удаляются.
5. Таблицы и карточки используют тонкие линии `#D5D7DA`.
6. Заголовки таблиц: `#181D27` фон, белый текст.
7. Чередование строк: `#FFFFFF` / `#F7F8FA`.
8. Источник должен быть на слайде или в заметке к слайду.
9. Каждый слайд должен иметь один главный визуальный носитель: таблицу, схему, карту, график, матрицу, timeline или bento-сетку.
10. Лого, номер и подвал задаются через общий helper, без ручной правки отдельных слайдов.

## Что обязательно проверять после сборки

- Текст не обрезан в PowerPoint.
- Все таблицы читаются при 100% масштабе.
- Нет текста меньше 10 pt.
- Источники присутствуют и привязаны к утверждениям.
- Заголовки читаются как история.
- Лого и номер стоят одинаково на всех слайдах.
- Нет теней и декоративных эффектов.
- Слайды редактируются как нативные элементы, если выбран editable-режим.
- Файл открывается в PowerPoint без предупреждений.

## Режимы экспорта

| Режим | Когда использовать | Проверка |
|---|---|---|
| HTML | витрина, PP Pages, быстрый просмотр | браузерный render 16:9 |
| Raster PPTX | быстрый PowerPoint для показа | PNG занимает весь слайд, нет полей |
| Native PPTX | рабочий редактируемый PowerPoint | объекты редактируются, текст не обрезан |
| PDF | финальная отправка без правок | страницы совпадают с approved render |

## Приёмка

Нативный PPTX считается готовым только после двух проходов:

1. `pp-text-critic` — язык, точность, анти-AI паттерны, англицизмы.
2. `pp-slide-critic` — заголовки-выводы, источники, плотность, шрифты, отсутствие теней, единая система.

Если в проекте появился удачный builder, его reusable-часть нужно перенести в Presentation Kit: helper’ы, константы, layout-паттерны, checklist. Сам клиентский материал в Git не уходит.
